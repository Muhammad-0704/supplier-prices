# Прайс-доска

Внутренний сервис склада: закупочные цены всех поставщиков на одном экране. Цены приходят из приходных накладных **1С:Фреш** через стандартный интерфейс OData, команда входит по логину с телефона или компьютера и видит одну и ту же доску.

- **Матрица**: сверху поставщики, слева товары, в ячейке последняя закупочная цена, изменение и дата. Лучшая цена залита зелёным, текущий поставщик обведён, устаревшая цена бледная.
- **Карточки** для телефона.
- **Ходовые / Все / Избранное / Скрытые**: редкие товары (без закупок дольше 30 дней) скрыты по умолчанию.
- **Панель товара**: все предложения, история цен на графике, кнопки «В избранное» и «Скрыть с доски».
- **Роли**: руководитель видит переплату в рублях, скрывает товары для всех и управляет командой; сотрудник видит цены, поставщиков и историю.
- **Живое обновление**: новая накладная из 1С появляется на доске у всех без перезагрузки.

Стек: Next.js 14 (App Router) на Vercel, Supabase (Postgres, вход, права через RLS, Realtime). Внешний вид по дизайн-системе «Прайс-доска»: токены лежат в `design/tokens.json`, компоненты в `src/components/ui.tsx`.

## Запуск за 6 шагов

### 1. Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (регион Central EU / Frankfurt).
2. Откройте **SQL Editor**, вставьте содержимое файла `supabase/migrations/0001_init.sql` и нажмите **Run**.
3. **Authentication → Sign In / Providers → Email**: выключите **Allow new users to sign up**. Аккаунты выдаёт только руководитель.
4. **Project Settings → API**: скопируйте `Project URL`, ключ `anon` и ключ `service_role` (он секретный).

### 2. Первый руководитель

1. **Authentication → Users → Add user → Create new user**: ваша почта, пароль, галочка **Auto Confirm User**.
2. В **SQL Editor** выполните `supabase/first-manager.sql`, подставив свою почту.

### 3. Vercel

1. Зайдите на [vercel.com](https://vercel.com) через GitHub, **Add New → Project**, выберите репозиторий `supplier-prices`.
2. В **Environment Variables** добавьте переменные из `.env.example`:

| Переменная | Что вписать |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL из Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ключ `anon` |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ `service_role` |
| `ONEC_MODE` | `mock` для первого запуска на демо-данных, потом `odata` |
| `CRON_SECRET` | любая длинная случайная строка |

3. **Deploy**. Откройте сайт, войдите, нажмите **«Обновить из 1С»**: в режиме `mock` доска заполнится демо-данными (216 товаров, 13 поставщиков).

### 4. Подключить настоящую 1С:Фреш

В 1С:Фреш стандартный интерфейс OData уже опубликован для всех баз, нужно только разрешить доступ. Делает это **владелец абонента**.

1. В приложении 1С откройте настройку стандартного интерфейса OData (обычно в разделе администрирования, пункт «Настройка стандартного интерфейса OData»).
2. Создайте служебного пользователя для OData и запомните логин и пароль.
3. Отметьте объекты, доступные через OData:
   - справочник **Номенклатура**
   - справочник **Классификатор единиц измерения**
   - справочник **Контрагенты**
   - документ **Приходная накладная**
4. Узнайте адрес OData: это адрес вашего приложения плюс `/odata/standard.odata`, например `https://1cfresh.com/a/sbm/1234567/odata/standard.odata`.
5. В Vercel поменяйте переменные: `ONEC_MODE=odata`, `ONEC_ODATA_URL`, `ONEC_USER`, `ONEC_PASSWORD`. Нажмите **Redeploy**.
6. Удалите демо-данные в Supabase **SQL Editor**: `truncate purchases, items, suppliers, sync_runs cascade;`
7. На доске нажмите «Обновить из 1С». Первая синхронизация заберёт накладные за `SYNC_DAYS_BACK` дней (по умолчанию 180).

Если 1С назовёт объект по-другому, сервис покажет ошибку с подсказкой. Точные имена объектов видны по адресу `<ONEC_ODATA_URL>/$metadata`; поправить их можно в `src/lib/onec/config.ts`.

### 5. Синхронизация по расписанию

- **Vercel Cron** (`vercel.json`) запускает синхронизацию раз в сутки, в 08:00 по Москве. На бесплатном тарифе чаще нельзя.
- **Каждые 10 минут**: включите в Supabase **Database → Extensions** расширения `pg_cron` и `pg_net`, подставьте адрес сайта и `CRON_SECRET` в `supabase/cron.sql` и выполните его.
- Кнопка «Обновить из 1С» работает всегда.

### 6. Команда

На странице **«Команда»** руководитель добавляет сотрудников: имя, почта, временный пароль, роль. Сотрудник входит сразу и может сменить пароль в разделе «Пароль».

## Как работает синхронизация

1. Читает справочники Номенклатура, Единицы измерения и Контрагенты. Категория товара — папка номенклатуры, в которой он лежит.
2. Читает приходные накладные с даты последней закупки минус 7 дней. Так подтягиваются правки задним числом.
3. Строки каждой полученной накладной переписываются целиком. Непроведённые и помеченные на удаление накладные убираются с доски.
4. Цена берётся из реквизита «Цена» строки табличной части «Запасы» в том виде, как она записана в документе.

**Дубли в 1С.** Если одна позиция заведена в 1С дважды, руководитель может склеить карточки: в Supabase в таблице `items` у дубля укажите в `merged_into` id основной карточки. Цены обеих карточек встанут в одну строку.

## Разработка

```bash
npm install
cp .env.example .env.local   # впишите ключи Supabase
npm run dev                  # http://localhost:3000
npm test                     # проверки расчётов и разбора OData
npm run mock:odata           # демо-сервер OData на http://localhost:8181/odata/standard.odata
npm run tokens               # пересобрать src/app/tokens.css из design/tokens.json
```

## Структура

```
design/tokens.json          токены дизайн-системы «Прайс-доска»
supabase/                   схема базы, права, расписание, первый руководитель
src/lib/onec/               OData-клиент 1С, разбор ответов, демо-база
src/lib/sync.ts             синхронизация 1С → Supabase
src/lib/derive.ts           лучшая цена, текущий поставщик, переплата, редкие товары
src/lib/board.ts            загрузка данных доски с учётом роли
src/components/             доска, панель товара, график, компоненты дизайн-системы
src/app/                    страницы: доска, вход, команда, пароль, API синхронизации
```
